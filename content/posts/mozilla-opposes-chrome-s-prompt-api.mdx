## Introduction

The web development community is abuzz with the news of Mozilla's opposition to Chrome's Prompt API. The API, which allows web applications to prompt users for input, has been a topic of debate among browser vendors and developers. In this post, we will summarize the events leading up to Mozilla's decision, explain why it matters to developers, and provide our take on the broader implications.

## What Happened

The Prompt API, introduced by Chrome, enables web applications to display system-level prompts to users, such as requesting access to the camera or microphone. While the API is designed to provide a seamless user experience, Mozilla has raised concerns about its potential for misuse. In a [GitHub issue](https://github.com/mozilla/standards-positions/issues/1213), Mozilla outlined its objections to the API, citing security and privacy risks.

Mozilla's primary concern is that the Prompt API could be used for phishing and other malicious activities. By allowing web applications to display system-level prompts, attackers could potentially trick users into revealing sensitive information or granting unauthorized access to their devices. Mozilla believes that the benefits of the Prompt API do not outweigh the potential risks and has therefore decided to oppose its implementation.

## Why It Matters to Developers

The debate surrounding the Prompt API has significant implications for web developers. On one hand, the API provides a convenient way to request user input, streamlining the user experience and reducing friction. On the other hand, the potential security risks associated with the API could have serious consequences for users and developers alike.

Developers who have already implemented the Prompt API in their web applications may need to reconsider their approach, especially if Mozilla's concerns are validated. This could lead to additional development time and resources being devoted to alternative solutions. Furthermore, the uncertainty surrounding the Prompt API's future could hinder the adoption of new web technologies, as developers may be hesitant to invest in APIs with unclear prospects.
